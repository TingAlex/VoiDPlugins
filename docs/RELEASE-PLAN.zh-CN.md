## 发布前后的检查

1. 从明确提交构建并测试，生成二进制、对应完整源码 ZIP 和 SHA-256。
2. 核对公开包包含许可证/依赖说明，没有本机配置、笔记、设备日志或私人探针。
3. 在目标 OTD 数据目录备份后升级，读回运行配置，确认页面实验关闭且稳定笔键仍可用。
4. 推送源码后检查 CI；若要更新默认分支或发布下载包，再分别核对 PR 和 Release 的实际状态。

## 仍值得补齐的验证

| 工作 | 完成标准 |

体验、舒适度和总体可用来自作者/用户反馈；它们不证明普遍效率提升，也不代替输入隔离或每个硬件组合的测试记录。
