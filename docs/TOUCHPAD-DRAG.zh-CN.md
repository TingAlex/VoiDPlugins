# 触控板三指拖框 / Touchpad three-finger drag

适用版本：**1.9.0 及以上**（OpenTabletDriver 0.6.7，Windows）。
参数位置：OTD → Filters → Precision Control (TingAlex Enhanced) → **第 08 组 触控板拖框**。

## 1. 它做什么

三指在触控板上拖动时，直接移动**实际的屏幕映射矩形**（也就是数位笔之后落笔的范围），不是只移动预览边框：

- 框的位置变，宽高和书写缩放（Scale）不变；
- 不移动鼠标、不滚动页面、不改变 OneNote 页面位置；
- 后台读取触点，不抢焦点，OneNote 前台时也能用；
- 抬指即停，没有惯性，也不会把没执行的位移补放到之后。

## 2. 使用前提

| 前提 | 说明 |
| --- | --- |
| Windows 精确触控板（Precision Touchpad） | 通过 Raw Input（`0x0D/0x05`）后台读取；普通触控板没有这套报告 |
| 笔离开数位板感应区 | 笔悬停时系统通常会抑制触控板，这是已接受的操作顺序 |
| 小范围映射已启用 | 映射关闭时不响应三指拖框 |
| 建议把 Windows 三指手势设为「无操作」 | 否则同一手势可能同时触发系统动作（任务视图等） |

## 3. 参数

| 界面字段 | Property ID | 范围 / 默认 | 作用 |
| --- | --- | --- | --- |
| 启用三指拖移 | `EnableTouchpadDrag` | 开/关，默认关 | 第 08 组总开关 |
| 移动倍率 | `TouchpadDragSensitivity` | 0.02–5，默认 0.25 | 1.0 = 横向划满触控板一次 ≈ 一个输出区域宽度；0.25 ≈ 一个映射框宽度 |
| 段落步长（像素，0=连续） | `TouchpadDragStepPixels` | 0–500，默认 0 | 大于 0 时框按该像素数一格一格跳；每格需越过 60% 才切换（10% 滞回） |
| 方向限制 | `TouchpadDragAxis` | 锁定主方向（默认）/ 自由（斜向）/ 仅水平 / 仅竖直 | 决定是否只允许单轴移动 |
| 锁轴比例 | `TouchpadDragAxisLockRatio` | 1–5，默认 1.5 | 主方向位移需达到次方向的多少倍才锁定；越小越容易锁、斜向越难保留 |
| 换轴比例（越大越黏） | `TouchpadDragAxisReleaseRatio` | 1.2–6，默认 2.5 | 已锁定时另一轴需超过本轴的多少倍才换向；越大越难被抖动带偏 |
| 参与手指数（隐藏） | `TouchpadDragFingers` | 2–5，默认 3 | 只能在配置 JSON 中修改，不显示在设置页 |

## 4. 判定逻辑

### 4.1 位移与倍率

每段拖动（落指到抬指）从**本段起点**计算总位移，再乘倍率取整，因此帧率、抖动和逐帧取整都不会累积误差：

```text
屏幕位移 = 触点位移 × 倍率 × 输出区域尺寸 ÷ 触控板逻辑范围
```

横纵分别计算，所以框会像手指一样移动，而不是被人为拉成正方形。

### 4.2 方向判定（为什么竖直不再带左右偏）

判定使用的是**原始触点位移**，不是屏幕像素。屏幕不是正方形（例如 3840×2160 时横纵倍率约差 1.78 倍），若用像素比较会把判定系统性拉向屏幕更宽的轴。

- **锁定主方向**：
  1. 起拖后比较横向 / 纵向位移；
  2. 主方向 ≥ 次方向 × **锁轴比例** → 锁定主方向；
  3. 锁定后只应用主方向位移，另一轴的残余直接丢弃（不累积、不后补）；
  4. 要换向，另一轴位移必须 > 本轴 × **换轴比例**；换向时重建基准，框不会跳。
- **自由（斜向）**：两轴同时生效，等同 1.8.0 之前的行为。
- **仅水平 / 仅竖直**：强制单轴，另一轴恒为 0。

### 4.3 段落感

`段落步长 > 0` 时，位移按步长量化成整格：

- 目标位置取最接近的整格；
- 翻格需要越过 60% 步长（10% 滞回），停在格子边界不会来回跳；
- 步长只影响三指拖框，不改旋钮步长或书写缩放。

### 4.4 起拖与结束

| 事件 | 行为 |
| --- | --- |
| 起拖 | 累计行程 ≥ 触控板逻辑范围的 1%（约 1.3 mm）才开始，避免误触；起拖帧只建立基准 |
| 抬指（空帧） | 结束本段，保留已移动的位置 |
| 手指数变化或触点 ID 变化 | 结束本段，要求重新建立基准 |
| 相邻帧间隔 > 40 ms | 视为一次停顿，重新开始判定，不补位移 |
| 笔尖接触书写 | 结束本段；拖框过程中不会出墨 |
| 映射关闭 / 笔键拖框进行中 | 不响应或结束本段 |
| 拖框进行中 | 旋钮、方向微移、鼠标重定位被拒绝，避免两种输入抢起点 |

## 5. 推荐组合

| 场景 | 方向限制 | 锁轴 | 换轴 | 步长 | 倍率 |
| --- | --- | --- | --- | --- | --- |
| 竖直换行、绝对不带横向偏移 | 锁定主方向 | 1.2 | 4.0 | 0–20 | 0.2–0.3 |
| 快速换区/搬框 | 锁定主方向 | 1.5 | 2.5 | 0 | 0.5–1.0 |
| 细调落点 | 锁定主方向 | 1.2 | 3.0 | 10 | 0.08–0.15 |
| 需要斜向移动 | 自由（斜向） | — | — | 0 | 0.2–0.4 |
| 临时只允许一个方向 | 仅水平 / 仅竖直 | — | — | 0–40 | 任意 |

想“更硬”（更难被带偏）：锁轴调小（1.1–1.2）、换轴调大（3–5）。
想“更松”（更容易换向或斜向）：锁轴调大（3–4）、换轴调小（1.5–2）。

## 6. 调参顺序建议

1. **先定倍率**：从 0.25 起，觉得搬不动就加、觉得太飘就减；目标是“一次自然划动 ≈ 想移动的距离”。
2. **再定方向**：默认「锁定主方向 + 锁轴 1.5」，竖直仍带偏就把锁轴降到 1.2、换轴升到 3–4。
3. **再定段落**：需要稳定步进（例如每次挪半行）就设 20–40；需要连续跟手就设 0。
4. **最后微调换轴**：觉得“想转横却转不过去”就降换轴，“一抖就乱转”就升换轴。

## 7. 故障排查

| 现象 | 检查 |
| --- | --- |
| 完全不动 | OTD 日志是否有 `Touchpad drag listening...`、`received its first precision touchpad frame`、`Touchpad drag started` |
| 只动一点点 | 倍率太小；或起拖 1% 行程阈值还没过 |
| 竖直仍带偏 | 方向限制是否为「锁定主方向」；锁轴比例降到 1.2 |
| 换向太费劲 | 换轴比例降到 2.0–2.5 |
| 斜向被吃掉 | 用「自由（斜向）」，或锁轴比例升到 3–4 |
| 边界来回抖 | 确认步长 > 0（10% 滞回生效）；或把步长调大 |
| 保存后不生效 | 重新应用设置；仍无反应则重启 OTD |

## 8. 限制与未验证

- 参与手指数默认 3，可在 JSON 中改为 2–5；四指配置未实测手感。
- 混合 DPI、多屏、输入区域旋转未验证；当前按单屏使用。
- 触控板拖框与 MagicMapper 的主动触觉无关，不改变触觉门槛。
- 真实手感、长时间使用疲劳、与其他手势软件的冲突需要按本机环境自测。

## 9. 回退

- 只关闭功能：取消勾选「08 触控板拖框 · 启用三指拖移」并应用。
- 完全回退插件：用安装前备份的 `plugin` 与 `settings.json` 覆盖 `%LOCALAPPDATA%\OpenTabletDriver`。
